# frame_quadfix, Halo MCC VR build

The base [frame_quadfix](../) layer plus three Halo additions, generated by [assemble.py](assemble.py) from `../quadfix.c`, [pad_part.c](pad_part.c) and [space_part.c](space_part.c). Built by [build.sh](build.sh) with clang and lld-link, no Windows SDK; the result is one x86-64 Windows DLL that works both under Proton on the Frame and on a Windows PC streaming to the Frame. Used by [Halo MCC](../../../games/halo-mcc/).

## What it adds

1. **Halo only.** On Windows an implicit OpenXR layer loads into every OpenXR app. This build checks its process and passes straight through anywhere except `MCC-Win64-Shipping.exe` (`FRAMEXR_ALL=1` overrides). It only opens its log there.
2. **View and D-pad bridge.** MCCVR turns its OpenXR actions into a virtual Xbox pad but has no Back or D-pad action. The layer adds an action set `framepad` (`view`, `dpad_up/down/left/right`) to the app's Touch suggestion, attach and every `xrSyncActions`, and ORs XInput Back / D-pad bits into what the game's `XInputGetState` import returns. The import slot is wrapped around the real `xinput` export, never around another shim, so the mod's own periodic re-claim of the slot chains through it without recursion. In Halo CE, Back is MCC's instant graphics switch and breaks the VR camera, so the bridge holds Back while the mod's log says CE is the active title. `FRAMEXR_PAD=0` turns the bridge off. Bind the Frame inputs with `/actions/framepad/in/<name>` in the Frame binding.
3. **`FRAMEXR_QUAD=norm`.** Keeps every quad's eye visibility, normalises its orientation, re-expresses quads placed in a `VIEW` reference space in the projection layer's space at the frame's display time, and while such a head-locked quad is present leaves the other quads out. SteamVR on the Frame rejected every Halo frame with the crosshair quad plus the head-locked menu panel (`XR_ERROR_POSE_INVALID`).

It also logs the layers of the first rejected frames in any mode (`REJECTED frame ...`) and keeps the base layer's Touch-only profile filter.

## Build

```bash
bash build.sh      # needs clang, lld-link and the OpenXR headers (/usr/include/openxr); the Frame has all three
```

Output: `out/frame_quadfix.dll` and `out/frame_quadfix.json`.

## Install

- **Frame:** [scripts/halo-mcc/install_build.sh](../../../scripts/halo-mcc/install_build.sh) copies both next to the mod; [mcc_controls.sh](../../../scripts/halo-mcc/mcc_controls.sh) registers the manifest in the prefix's `system.reg` (`HKLM\Software\Khronos\OpenXR\1\ApiLayers\Implicit`, MCC closed).
- **Windows:** [scripts/halo-mcc/windows/install-pc.ps1](../../../scripts/halo-mcc/windows/install-pc.ps1) copies both and writes `register-frame-layer.reg`. Machine-wide (`HKEY_LOCAL_MACHINE`) is required: the MCCVR launcher runs as administrator, starts MCC elevated, and the OpenXR loader ignores `HKEY_CURRENT_USER` layers in elevated processes.

`DISABLE_FRAME_QUADFIX=1` turns the layer off entirely.
